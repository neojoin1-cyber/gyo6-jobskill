## 1. 재현과 원인

- 배포 전에 열린 웹 체험 탭에서 교사 화면 진입 시 삭제된 `TeacherShell` 해시 파일 요청을 재현했다.
- 최상위 역할별 화면과 일부 교사용 하위 화면이 공통 청크 복구기 밖에서 로드되고 있었다.
- 기존 오류 화면의 `최신 버전 불러오기`는 일반 새로고침만 수행해, 낡은 서비스워커가 이전 `index.html`을 다시 반환할 수 있었다.
- URL에 체험 역할 정보가 남은 경우 일반 교사 세션을 체험 역할 전환으로 오인할 수 있는 잠재 조건도 확인했다.

## 2. 수정

- 학생·교사·학교관리자·운영자 최상위 화면과 교사용 지연 로딩 화면을 모두 `lazyChunk` 복구기로 통일했다.
- 청크 로딩 실패 시 서비스워커 등록과 Cache Storage를 정리하고 `app_retry` 캐시 우회 주소로 교체 이동한다.
- 오류 경계와 복구 안내 화면의 수동 버튼도 같은 최신 버전 복구 절차를 사용한다.
- 성공적으로 화면을 불러오면 재시도 표식을 지워 이후 배포에서도 다시 한 번 자동 복구할 수 있게 했다.
- 체험 역할 전환은 현재 로그인 사용자가 실제 공개 체험 계정일 때만 실행한다.

## 4. 회귀 방지 조건

- 최상위 `TeacherShell`이 공통 청크 복구기를 사용하지 않으면 빌드를 차단한다.
- 복구기가 서비스워커 해제, 캐시 우회 재진입, 성공 후 재시도 표식 해제를 갖추지 않으면 빌드를 차단한다.
- 일반 교사 계정을 체험 역할 전환으로 판단하면 체험 격리 게이트를 실패시킨다.

## 최종 판정

이번 오류는 테스트 계정의 데이터 문제가 아니라 장시간 열린 웹 탭과 새 배포 사이의 정적 파일 버전 불일치였다. 수정본은 같은 상황에서 최신 앱을 자동 회수하도록 변경됐으며 웹 긴급 수정 배포가 가능하다.
