# 소유자 실행 지시서 — 검증 전용 계정 신설

**요청** 클로드 코드(적대적 검증자) · **수행** 소유자 · **작성** 2026-09-02
**기준선** `9797477fe73a` (4.8.14 / `b7c1b26` / build 29804584)

---

## 0. 왜 필요한가

앱은 `isTrial` 인 계정에서 **정식 경로 일부를 아예 실행하지 않는다**
(`src/screens/student/StudentShell.jsx:133`). 그래서 체험 계정으로는 아래를 검증할 수 없다.

| 미검증 범위 | 원장 ID |
|---|---|
| 학생 학습 위치 전송 · 교사 화면의 "현재 학습 중" | LIMIT-001 |
| 교사가 낸 미션이 학생에게 그대로 가는가 | TCH-001 · TCH-003 |
| 기기 동기화 22건 | SYNC 전체 |
| 작성본·오답의 저장·잔존 | SEC 정식 계정분 |
| 안드로이드 앱의 로그인 이후 화면 | AND-103 |

또한 `verify-production-flows` 의 **52개 체크 중 21개**(수업 시작·문항 제출·메시지 왕복·
오답 누적·자소서 작성본·학교관리자 회원관리)는 체험 토큰 모드에서 실행되지 않는다 → OPS-001.

---

## 1. 내가 하지 않는 것

계정 생성과 비밀번호 입력은 **내가 하지 않는다.** 아래 절차는 소유자가 직접 실행한다.
만든 뒤 세션을 넘기는 방법은 4절에 있다 — 그 방법에서도 비밀번호는 나에게 오지 않는다.

---

## 2. 만들 것 (최소 구성)

| 대상 | 개수 | 표기 규칙 |
|---|---|---|
| 교사 | 1 | 이름 `[검증]교사` |
| 학생 | 2 | 이름 `[검증]학생1`, `[검증]학생2` |
| 학급 | 1 | 이름 `[검증]전용학급` — 실제 학급과 절대 섞지 않는다 |

- 이메일은 실제 학생·교사와 구분되는 도메인을 쓴다(예: `verify-teacher@…`, `verify-s1@…`).
- 닉네임은 전국 랭킹에 뜨므로 `[검증]` 을 넣어 실제 학생과 구분한다.
- 검증이 끝나면 6절 절차로 지운다.

---

## 3. 만드는 방법 — 앱 화면 경로 (권장)

앱이 실제로 쓰는 경로와 같아 스키마·승인 흐름까지 함께 확인된다.
주소: `https://gyo6.kr/apps/sugar-salt/?entry=member`

1. **교사 가입** — 회원가입 → 선생님 → 이메일·비밀번호·이름(`[검증]교사`)·학교 선택
   (내부적으로 `auth.signUp` → `rpc_create_teacher_profile(p_display_name, p_school_id)`)
2. **교사 승인** — 학교관리자 계정으로 로그인해 방금 만든 교사를 승인한다.
   (승인 전에는 로그인해도 기능이 잠긴다)
3. **학급 생성** — 승인된 교사로 로그인 → 학급 만들기 → 이름 `[검증]전용학급`
   (`rpc_create_class`). 만들어진 **학급 코드**를 적어 둔다
4. **학생 가입 ×2** — 회원가입 → 학생 → 학급 코드로 `[검증]전용학급` 선택,
   이름 `[검증]학생1` / `[검증]학생2`
   (`auth.signUp` → `rpc_student_join(p_display_name, p_nickname, p_class_id)`)
5. **학생 승인** — 교사 계정에서 대기 중 학생 2명을 승인한다

> 3~5단계에서 승인이 빠지면 로그인은 되지만 화면이 비어 검증이 헛돈다. 승인까지 끝내야 한다.

---

## 4. 나에게 넘기는 방법 — 비밀번호를 주지 않는 두 가지

**방법 A (권장) — 보이는 창에 직접 로그인**
1. 나에게 "A로 진행" 이라고 알려 준다
2. 내가 창이 보이는 브라우저를 띄워 로그인 화면까지 연다
3. 소유자가 그 창에 직접 이메일·비밀번호를 입력해 로그인한다
4. 내가 **로그인된 세션 상태만** 파일로 저장해 이후 자동화에 재사용한다
   (비밀번호는 내 기록·증거·저장소 어디에도 남지 않는다)
5. 계정 3개(교사·학생1·학생2) 각각 한 번씩 반복한다

**방법 B — 환경변수**
소유자가 `D:\apps\sugar-salt-campus\.env.local` 에 직접 아래를 적는다(이 파일은 저장소에 커밋되지 않는다).

```
DEMO_TEACHER_EMAIL=
DEMO_STUDENT_EMAIL=
DEMO_ADMIN_EMAIL=
DEMO_PASSWORD=
```

나는 이 값을 읽는 스크립트만 실행하고, 화면 출력·증거 파일에서 마스킹한다.
프로젝트의 `scripts/verify-production-flows.mjs` 가 이미 이 변수명을 쓴다.

---

## 5. 계정을 받으면 내가 바로 하는 일

1. `npm run verify:production-flows` **정식 모드**(비밀번호 경로) — 미실행 21개 체크 실행
2. LIMIT-001 — 학생이 자율학습 중일 때 교사 화면에 실제 학습 위치가 뜨는지
3. TCH-001 · TCH-003 — 교사가 단원을 지정해 미션을 내고, 학생 화면에 무엇이 오는지 왕복 확인
4. SYNC 22건 — 기기 상태 동기화, 경계값(399KB/401KB·1.19MB/1.21MB·249/251·23:59/24:01·71:59/72:01)
5. SEC 정식분 — 작성본·오답의 잔존과 학생 간 격리(SEC-02·SEC-06)
6. AND — 안드로이드 앱 로그인 이후 화면(업데이트 데이터 보존, 저장 대기 중 단절, 하단탭 safe area)

---

## 6. 검증이 끝난 뒤 정리

1. 교사 계정에서 `[검증]전용학급` 의 학생 2명 제거
2. 학교관리자 계정에서 `rpc_admin_delete_member` 로 계정 3개 삭제
   (앱 화면의 회원 관리에서 같은 기능을 쓸 수 있다)
3. 삭제 후 내가 SEC-08(삭제 후 잔존) 항목으로 **정말 지워졌는지** 확인한다
   — 이 정리 작업 자체가 검증 항목 하나다

---

## 7. 하지 않을 것

- 실제 학생·교사 계정을 빌려 쓰지 않는다
- 검증 계정으로 실제 학급·실제 학생 데이터에 접근하지 않는다
- 비밀번호를 대화·커밋·증거 파일에 남기지 않는다
