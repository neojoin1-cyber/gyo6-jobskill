# PC·모바일 연계 운영 설계

## 결론

학생과 교사 모두 같은 계정으로 PC 웹과 앱을 함께 사용하는 방향이 적합하다. 기기 제한은 `PC 1대 + 모바일·태블릿 1대`의 두 슬롯으로 두되, 이것만으로 서버 부하를 해결하려 해서는 안 된다. 슬롯제는 계정 공유와 무제한 동시 접속을 막고, 실제 부하는 로컬 우선 저장·묶음 동기화·정적 자산 캐시로 줄인다.

## 기기 정책

- 계정마다 `desktop` 1슬롯과 `mobile` 1슬롯을 둔다. 태블릿은 모바일 슬롯에 포함한다.
- 브라우저 지문이나 기기 고유번호를 강제로 수집하지 않는다. 최초 인증 때 만든 난수 기기 키와 서버의 해시만 저장한다.
- 새 기기로 바꿀 때는 비밀번호 재확인 또는 학교 인증 후 기존 슬롯을 교체한다.
- 분실 기기는 사용자와 학교 관리자가 즉시 로그아웃시킬 수 있어야 한다.
- 수업 중 PC와 앱의 동시 접속은 허용하되, 같은 문서의 동시 편집은 한쪽만 편집권을 갖게 한다.
- 공용 PC는 `이번만 사용`으로 로그인하고 브라우저 종료 시 장기 토큰을 폐기한다.
- 학교가 승인한 컴퓨터실 PC는 개인 PC 슬롯을 차지하지 않는 `학교 공용 세션`으로 연다. 학교·학급 확인, 짧은 만료 시간, 자동 로그아웃, 로컬 문서 잔존 금지를 함께 적용한다.
- 학교 공용 세션이 없다면 좌석이 바뀔 때마다 PC 슬롯을 교체해야 하므로 실제 수업 도입을 방해한다.

## 기기별 역할

| 작업 | PC 웹 | 앱·태블릿 |
|---|---|---|
| 자기소개서 작성·비교·교사 첨삭 확인 | 주 작업 | 조회·짧은 수정 |
| 1분 자기소개·지원동기 대본 관리 | 주 작업 | 녹음·반복 연습 |
| 자율학습·진단·모의고사 | 지원 | 주 작업 |
| 수업 따라가기 | 교사 투사·학생 개별 화면 | 학생 참여 |
| 진행 현황·교사 피드백 | 넓은 종합 화면 | 알림·핵심 확인 |

## 저장과 충돌 방지

- 자기소개서와 면접 답변은 `지원 프로젝트/답변 세트` 단위로 버전 번호를 둔다.
- 입력 중에는 3~5초 디바운스로 로컬에 저장하고, 서버에는 변경 묶음을 30~60초 또는 화면 이탈 시 전송한다.
- 서버 저장 시 `base_version`을 확인한다. 다른 기기에서 먼저 수정했다면 덮어쓰지 않고 `충돌 사본`을 만든다.
- 한 문서를 편집하는 동안 2분짜리 편집 임대를 발급하고 활동 시 연장한다. 다른 기기는 읽기 전용과 `이 기기에서 이어쓰기` 선택을 제공한다.
- 네트워크가 끊기면 로컬 대기열에 쌓고 재연결 후 순서대로 동기화한다.

## 부하 대책

- 현재의 `rpc_bootstrap` 1회 조회와 `rpc_sync_progress` 묶음 전송 구조를 PC에도 그대로 사용한다.
- 수업 참여 신호는 수업 중에만 보내고 현재 150초 주기와 상태 변경 즉시 전송 원칙을 유지한다.
- 학습 이미지·음원·문항 데이터는 앱 번들 또는 CDN 캐시에 두고 서버 DB에서 반복 조회하지 않는다.
- 교사 수업 연결은 화면 콘텐츠 전체가 아니라 과목·모드·단원·카드 ID만 전송한다.
- 자기소개서 자동 저장은 글자마다 전송하지 않고 변경량을 묶는다.
- 기기 슬롯 수보다 `요청 빈도`, `쓰기 묶음`, `정적 자산 캐시`가 서버 비용에 더 큰 영향을 준다.

## 도입 순서

1. 학생·교사 공용 반응형 PC 웹과 두 슬롯 등록 화면
2. 자기소개서 프로젝트·면접 답변 세트의 PC 편집 및 앱 연계
3. 버전 충돌 방지와 편집 임대
4. 학습 진행·오답·피드백 묶음 동기화
5. 학교 관리자용 기기 해제·접속 감사 화면

## 출시 기준

- PC와 앱에서 같은 문서를 번갈아 수정해도 내용이 사라지지 않는다.
- 두 기기 동시 접속이 학습 기록과 XP를 중복 생성하지 않는다.
- 기기 교체·분실·공용 PC 사용 동선이 학생 혼자서도 이해 가능하다.
- 30명 한 학급과 전국 동시 수업 부하 시험에서 읽기·쓰기·실시간 연결이 각각 설정한 한도 안에 들어온다.
