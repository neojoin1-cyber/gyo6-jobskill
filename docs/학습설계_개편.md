# 학습 설계 개편 — 무작위에서 학습 신호로

2026-08-21

앱이 "오류가 없다"는 것과 "학습에 도움이 된다"는 것은 다른 말이다. 화면은
멀쩡했지만 **무엇을 언제 왜 내주는지**에 설계가 없었다. 세 가지를 고쳤다.

## 1. 오늘의 도전 — 학습 신호로 고른다

카드는 "5문항 · 빈출 우선 출제"라고 말했지만 실측하니 셋 다 사실이 아니었다.

| 카드가 말한 것 | 실제 |
|---|---|
| 빈출 우선 출제 | `examPriority === 'high'` 문항 **0개** — 작동한 적 없음 |
| (전 과목에서) | NCS 1,445문항 중 후보 **0개**, `questionMode` 필터가 전부 제외 |
| — | 직업공통 751개 중 **앞에서 300개만**, 나머지 60%는 영원히 안 나옴 |
| — | 오답·취약영역·복습예정·진도를 **전혀 보지 않음** |

`src/lib/dailyChallenge.js` 를 다시 썼다. 후보 풀 300 → **2,057문항**,
다섯 자리를 목적별로 나눠 담고 **왜 이 문항이 나왔는지 학생에게 보여 준다.**

    2문항  복습 예정(간격 반복 due)  🔁 잊을 때가 됐어요
    1문항  미해결 오답               📌 지난번에 틀렸어요
    1문항  최근 학습한 영역          📖 요즘 공부한 곳
    1문항  취약 영역                 🎯 약한 영역이에요

몫이 비면 다음 순위가 흡수한다. 신호가 없는 첫 사용자는 '확인' 수준부터 준다.

두 은행이 서로 다른 영역 이름을 써서(26v1 7영역 vs 구 10영역) 신호가 은행
경계를 넘지 못하던 문제도 함께 고쳤다 — 자기개발능력↔자기관리능력,
정보·기술↔디지털, 자원관리·조직이해↔문제해결로 이름을 맞춘다.

## 2. 요구 수준마다 다른 연습

`demandLevel`(확인·적용·종합)을 매겨 두고도 학습 화면은 1,445문항을 전부
똑같이 다뤘다. 보기 고르고 → 채점하고 → 해설 읽기. 세 수준을 갈랐다.

| 수준 | 연습 방식 | 채점 전에 하는 일 |
|---|---|---|
| 확인 (24%) | 🔎 찾아 읽기 — 반복해서 빨라지기 | 자료에서 근거를 눈으로 짚기 |
| 적용 (45%) | 🧭 상황에 옮기기 — 자기설명 | **왜 그 답을 골랐는지** 이유 고르기 |
| 종합 (31%) | 🧩 근거 세우기 | **판단의 근거를 한 줄로 적기** |

셋 다 답을 보기 **전에** 학생이 무언가를 내놓게 한다. 정답을 본 뒤에는
"나도 그렇게 생각했다"고 느끼기 쉬워서, 미리 남긴 것과 견줘야 어긋난 자리가 보인다.

이유 칩에 '확신 없이 골랐어요'를 넣은 것은 일부러다. 찍어서 맞힌 문항은
학생 눈에 '아는 문항'으로 남는데 실제로는 가장 위험하다. 표·수치 문항에는
'눈에 띄는 항목만 확인하고'를 둔다 — 도표에서 가장 흔한 실수다.

**말한 대로 동작하게 했다.** "짧은 간격으로 다시 물어볼게요"라고 해 놓고
코드가 같으면 그게 거짓말이므로, 간격 반복도 수준별로 갈랐다.

    확인  정답 5회 → 1, 2, 5, 12, 30일 뒤
    적용  정답 5회 → 1, 3, 8, 20, 50일 뒤
    종합  정답 5회 → 1, 4, 11, 28, 70일 뒤

## 3. 그 과정에서 찾아낸 문항 고장

학습 화면을 학생처럼 밟다가 드러난 것들이다. 전부 자동 검사로 막아 두었다.

| 고장 | 규모 | 조치 |
|---|---|---|
| 지문·보기·힌트가 통째로 발문에 들어가 보기가 두 번 그려짐 | 8문항 | 자료/발문/해설로 분리 |
| **"다음 조건을 만족하는…"인데 그 조건이 없음** | 129문항 | 원본 교재에서 자료 복원 |
| 안내 문장이 자료 맨 뒤에 붙어 읽는 순서가 뒤집힘 | 50문항 | 앞으로 옮김 |
| 해설이 정답과 다른 답을 계산해 놓음 | 5문항 | 검산 후 키·해설·보기 정정 |
| 조건이 답을 하나로 좁히지 못함 | 2문항 | 출제 제외(까닭 기록) |
| 제작용 라벨이 학생 화면에 노출 | 351곳 | 제거 |

`scripts/gate-question-quality.py` 에 검사를 넣어 같은 고장이 다시 들어오면
빌드가 실패한다. 미검수 은행 면제도 **설명이 아니라 결과로** 확인한다 —
번들을 실제로 돌려 출제 풀에 지적 문항이 섞였는지 본다.

## 남은 것

- `data/job-variants.json` 같은 중첩 구조 파일은 게이트의 `load()` 가 문항으로
  보지 못해 검사 밖에 있다. 변형 문항이 학생에게 나가는 경로를 확인해야 한다.
- 해설에 수치가 아예 없는 설명형 해설 33건은 오류는 아니지만 불친절하다.
- 요구 수준은 아직 **문항이 요구하는 인지 작업**의 분류다. 학생 응답이 쌓이면
  정답률로 보정해야 한다.

# 2차 — 출석 의례·게임·교사 자료 (2026-08-21)

## 학생편에서 고친 것

| 지적 | 원인 | 조치 |
|---|---|---|
| 식음료가 아직 메뉴에 보임 | 오답노트 필터 칩이 손으로 적혀 있어 폐지 과목이 남음 | 카탈로그에서 생성 |
| — (같이 발견) | 폐지 필터가 '약한 영역'에만 걸려 목록엔 품질경영 오답 100여 건이 그대로 | 목록·집계 모두 적용 |
| 복습 카드가 교재 메뉴로 감 | `onGoStudy()` 만 호출. 개수만 세고 문항을 불러올 방법이 없었음 | `getDueItems()` + 복습 세션 |
| — (같이 발견) | 배지 11개인데 세션은 8문항 | 배지를 세션과 같은 기준으로 계산 |
| 오답노트에서 처리할 수 없음 | 읽고 마는 목록이라 오답이 쌓이기만 함 | 다시 풀기 · 이해했어요(정복) |
| — (같이 발견) | 약점 1위가 `교육부 직업공통능력 인증 62개` — 과목명이 영역 자리에 | 문항 인덱스에서 영역 복원 |

## 출석과 게임

출석은 버튼이 아니라 2분짜리 의례로 만들었다. 훈화 한 편(90편)을 읽고, **그 글을
읽어야만 풀리는 문항** 하나를 푼다. 틀려도 출석은 된다 — 출석은 성적이 아니라
습관이기 때문이다. 훈화는 한 바퀴 다 돌기 전에는 같은 글이 나오지 않는다.

스피드 퀴즈는 규칙 자체를 학습 목표로 삼았다. 학습 화면은 정확도만 다루는데
실제 필기시험은 **시간이 모자라서** 틀린다. 60초, 맞히면 +10점, 틀리면 3초 감점
(찍으면 손해), 연속 보너스. 종합 수준 문항과 표·긴 지문은 빼서 731문항을 골랐다.
점수는 주간 XP로 환산돼 **이미 있는 주간 랭킹** 위에서 반 대항전이 된다 —
새 표를 만들지 않았다.

## 교사 자료

덱은 `표지 → 전략 → 문항 8 → 출구 질문`뿐이었다. 세 가지를 더했다.

- **한눈에 보기** — 63차시 개념 도식. flow/matrix/compare 세 꼴만 쓰고,
  SVG는 `diagram_svg.py` 가 그린다. 도식을 SVG 문자열로 받으면 좌표가 어긋나므로
  **무엇을 그릴지만 구조로 받는다.**
- **시험에는 이렇게 나온다** — 기관 유형별 출제 방식·함정·읽는 법 + 업무 사례.
  실제 기출 문항은 **싣지 않는다.** 지어낸 기출을 사실처럼 싣는 것보다
  "어떻게 묻는지"를 정확히 적는 편이 낫다. 슬라이드에 그 사실을 명시한다.
- **학생 앱에서 이어서** — 그 차시로 바로 가는 QR. 앱에 주소 라우팅이 아예 없어
  `?open=study&subject&area&lesson` 을 새로 만들었다. 링크로 들어오면 교재·모드·
  영역 고르기를 건너뛴다. 링크가 틀리면 조용히 무시하고 평소 화면을 준다.

아침 조회 자료 90편은 **학생 앱과 같은 원고**를 쓴다(`data/morning-talks.json`).
따로 만들면 두 배로 들고 무엇보다 내용이 어긋난다 — 학생은 A를 읽었는데 교사는
B를 읽는 일이 생긴다.

## 그 과정에서 또 찾은 문항 결함

| 결함 | 규모 |
|---|---|
| 보기 본문에 `A.`·`B.` 가 들어 있어 화면에 번호가 두 번(`1. A -14`) | 506문항 |
| `자료 … 문제. 질문` 이 발문에 붙어 있고 보기가 두 번 나옴 | 64문항 |
| 발문의 `문제.` · `(교재 빠른 진단문항)` 라벨 | 44곳 |
| 해설이 정답과 다른 답을 계산 | 1문항 추가 |

보기 번호 표기는 화면마다 달랐다(학습 화면 1·2·3, 복습 화면 A·B·C, 해설은 "2번").
해설 표기에 맞춰 **번호로 통일**했다.

## 아직 남은 것

- `_data/app-link.json` 의 `baseUrl` 이 비어 있어 덱의 QR 슬라이드가 생성되지 않는다.
  학생 앱의 공개 주소를 넣어야 한다. **주소를 지어내지 않았다** — 틀린 QR은 학생
  스무 명을 한꺼번에 빈 페이지로 보낸다.
- `data/job-variants.json` 같은 중첩 구조 파일은 게이트의 `load()` 가 문항으로
  보지 못해 검사 밖에 있다.

# 3차 — 모드 구분·전수 검증·인증 전환 (2026-08-21)

## 1. 학습/게임 모드

같은 두 모드를 화면마다 다르게 불렀다 — `학습/문제`, `학습/게임`, `이론/퀴즈/실습`.
이름이 셋이면 같은 것인지 다른 것인지 알 수 없고, **무엇이 다른지는 아무 데도
적혀 있지 않았다.**

이름과 목적을 `src/lib/studyModes.js` 한 곳에서 정하고 화면들이 가져다 쓴다.

| | 익히기 📖 | 도전하기 🎮 |
|---|---|---|
| 하는 일 | 답을 떠올린 뒤 펼쳐 확인 | 고르고 확인하면 즉시 채점 |
| 남는 것 | **없음** | XP · 오답노트 · 복습 일정 |
| 색 | 청록 | 남보라 |
| 띠 문구 | "채점도 기록도 없어요" | "틀린 문항은 오답노트로" |

틀려도 괜찮은 자리와 기록이 남는 자리를 구분해야 마음 놓고 틀려 보고
마음먹고 점검한다 — 그것이 두 모드를 나누는 이유다. 도전하기에는 실시간
`n개 맞힘 · n/총` 을 띄운다("n개 선택"만으로는 잘하고 있는지 알 수 없었다).

## 2. 전 과정 시범사용에서 나온 것

새로 넣은 것을 학생처럼 처음부터 끝까지 밟았다. 그 과정에서 나온 결함:

| 결함 | 조치 |
|---|---|
| 같은 문항인데 모드에 따라 배지가 다름(익히기=요구수준, 도전=난이도) | 두 배지를 양쪽 모두에 |
| 오늘의 도전·면접·교재읽기·차시퀴즈가 보기를 A·B·C 로 표기 | 전 화면 번호로 통일 |
| 해설의 `정답: ④번` 원문자 1,325건 | `정답: 4번` 으로 정규화 |
| "이해했어요" 로 뺐는데 "총 55개 오답"은 그대로 | 집계·약점 분석까지 반영 |

훈화 회전은 90일을 돌려 확인했다 — **90일 동안 90편, 중복 0**, 91일차부터
새 순서. 같은 날 두 번 열어도 같은 글이 나온다.

교사 보조자료 63건도 에이전트 보고를 믿지 않고 직접 검사했다 — 차시 불일치 0,
도식 렌더 경고 0, flow·matrix·compare 21건씩, 실존 기업명·연도 기출 주장 0건.

## 3. 메일 인증 — Cloudflare Access → Supabase

### 왜

Zero Trust 무료 등급은 **좌석 50명**이 상한이다. 학교가 늘어 교사가 51명이
되는 순간 로그인이 막히는데, 그때는 이미 수업 중이다. 앱이 이미 Supabase 로
교사를 관리하므로 그쪽으로 옮긴다.

### 어떻게

`gate/` → `_deploy/functions/` 로 복사되어 **Pages Functions** 가 된다. 정적
파일이 나가기 **전에** 실행되므로 로그인하지 않은 요청은 파일 자체를 받지
못한다. 정적 사이트에서 스크립트로 가리는 것은 방어가 아니다.

    쿠키의 액세스 토큰 → JWKS(ES256) 서명 검증 → 만료 시 갱신하며 교사 권한 재확인
    로그인 → 이메일 6자리 인증번호(Supabase) → 서버가 확인 후 HttpOnly 쿠키

비밀키가 필요 없다(ES256 공개키 검증). 토큰은 브라우저 스크립트가 만지지 않는다.

### 하마터면 정답이 공개될 뻔한 지점

`wrangler pages deploy _deploy` 로 **바깥에서** 배포하면 wrangler 가
`functions/` 를 현재 작업 디렉터리 기준으로 찾아 그냥 지나친다. 정적 파일만
올라가고 **접근 통제가 통째로 빠진다.** 실제로 처음 배포가 그랬다.

내용이 없는 시험용 사이트를 따로 만들어 확인해서 잡았다. 진짜 자료로
시험했다면 그 순간 정답이 공개됐을 것이다. 이제 `_deploy` **안에서** 배포하고,
출력에 `✨ Uploading Functions bundle` 이 보이는지 확인한다.

검증한 것: 인증 없는 모든 경로 302(본문 0바이트) · 위조 쿠키 302 ·
서명 없는 JWT 302 · 미가입 주소 403 · 로그인 화면만 200.

### 메일 인증을 기본에서 뺀 이유

처음에는 이메일 인증번호만 만들었다. 그러면 규모가 커질수록 메일 발송이
병목이 된다 — 수천 명이 한 시간에 몰리면 발송 한도에 걸려 **수업 중에 로그인이
막힌다.** 바꾸려던 이유와 똑같은 사고다.

교사는 이미 앱에 가입해 로그인해 있다. 그 자격을 그대로 쓰면 메일이 필요 없다.

| 길 | 언제 | 메일 |
|---|---|---|
| **앱에서 바로 열기** | 교사 화면 → `수업자료` | 없음 |
| **비밀번호 로그인** | PC 브라우저 | 없음 |
| 이메일 인증번호 | 비밀번호를 잊었을 때 | 예비 |

앱에서 열 때는 로그인 화면조차 뜨지 않는다. 토큰을 주소의 `#` 뒤에 실어
넘기고(서버 기록에 남지 않는다), 받는 쪽이 확인해 쿠키를 심고 주소창에서
즉시 지운다. **앱에서 교사로 가입해 승인받으면 그것이 곧 자료 접근 권한이다.**

권한은 매번 `profiles.role` 로 확인하므로, 앱에서 승인을 취소하면 자료도 닫힌다.
좌석 상한도 없고 메일 한도도 없다.

### 남은 절차 (사용자가 해야 함)

Access 애플리케이션 삭제는 **wrangler 의 OAuth 토큰에 `access:write` 권한이
없어** 스크립트로 할 수 없다(zone Access API 403 확인). 대시보드에서 지워야 한다.
순서는 `DEPLOY.md` 참고.

### 검증 중 잡은 보안 구멍

사용자에게 "교실 컴퓨터에서 로그인해 보세요"라고 시키는 대신 직접 시험했다.
로컬 앱에 로그인돼 있던 **학생 계정의 진짜 토큰**을 꺼내 쿠키에 넣어 보니
수업 덱이 그대로 열렸다(HTTP 200, 정답 포함).

미들웨어가 JWT **서명만** 확인하고 권한은 토큰이 만료됐을 때만 봤다.
서명이 멀쩡한 토큰은 학생도 가지고 있으므로 그것만으로는 아무것도 막지 못한다.

모든 요청에서 `profiles.role` 을 확인하도록 고쳤다(토큰별 5분 캐시로 왕복 제거).
재시험에서 같은 토큰이 `/login` 으로 튕기는 것을 확인했다.

RLS 도 함께 확인했다 — 학생 토큰으로는 자기 행 하나만 읽힌다.
즉 교사 토큰이면 `role: "teacher"` 가 나와 통과하고, 그 외에는 막힌다.

# 4차 — 과목별 학습 체계 정합성 (2026-08-21)

## 근본 원인 — "콘텐츠가 없어서"가 아니었다

"NCS 자율학습은 공부 단계 없이 바로 문제로 간다"는 지적을 파 보니, 요점정리는
**이미 있었다.** 다만 저장된 열쇠가 **구 NCS 10영역 이름**(`area:의사소통`)인데
앱은 **26v1 이름**(`의사소통능력`)으로 찾고 있었다.

    ✗ 의사소통능력  ✗ 수리능력  ✗ 문제해결능력  ✗ 자기관리능력
    ✗ 대인관계능력  ✗ 디지털능력  ✓ 직업윤리

7영역 중 6영역이 빈 화면이었고, 이름이 바뀌지 않은 직업윤리 하나만 우연히 맞았다.
**26v1 개편 때 문항은 옮겼는데 요점정리는 따라오지 않은 것이다.**

이름을 이어 주자 곧바로 7/7 이 됐다. 합쳐진 영역은 원래 것들을 이어 붙인다
(디지털 ← 정보·기술, 문제해결 ← 문제해결·자원관리·조직이해).

| 과목 | 문항 | 요점정리 | 진단 | 모의 |
|---|---|---|---|---|
| 교육부 직업공통 | 751 | 42/51 단원 | 215문항 + 빠른 40 | 342문항·240분 |
| NCS 26v1 | 1,443 | **7/7 영역** (1/7 → 7/7) | 40문항 학습진단 | 있음 |
| 채용 필기 | 445 | 9/9 영역 | 40문항 학습진단 | 트랙별 |

## 남은 진짜 공백 — 요점정리 단위가 다르다

직업공통은 **단원(51개)** 단위, NCS 는 **영역(7개)** 단위다. 그래서 NCS 에서
`문서소통능력`을 골라도 의사소통능력 **영역 전체** 요점이 나온다. 없는 것보다
낫지만 겨냥이 굵다.

지금은 **그 사실을 화면에 밝힌다.**

    의사소통능력 영역 요점
    의사소통능력 전체에서 꼭 알아야 할 것을 모았습니다.
    문서소통능력만이 아니라 영역 전체를 다룹니다.

숨기고 "문서소통능력 요점"인 척하는 것보다, 무엇을 보고 있는지 알려 주는 편이
학생에게 정직하다. 하위능력(21개) 단위 요점정리는 다음 과제다.

직업공통에서 요점정리가 없는 단원 9개: `C01-0` `C33-32` `JC26-KO-LISTEN`
`JC-SYN-KO` `JC-ENG-SUP` `JC26-MATH-VISUAL` `JC-SYN-MA` `JC-SYN-PS`
`JC26-JOB-ADAPTATION` — 대부분 나중에 보강한 묶음(종합·듣기·도표)이라
요점정리가 함께 만들어지지 않았다.

## 진단평가 문구 — 학년이 아니라 목적을 먼저

3학년 인증진단을 목표로 고른 학생에게 진단평가 칸이 이렇게 말하고 있었다.

    1·2학년 215문항 자가진단과 앱 빠른 진단입니다.

첫마디가 "1·2학년"이라 자기 것이 아닌 것처럼 읽힌다. 실제로는 3학년도
약점을 빠르게 찾는 데 쓴다. **목적을 먼저, 규모를 나중에** 말하도록 바꿨다.

    약한 영역을 빠르게 찾는 단계입니다.
    앱 빠른 진단 40문항, 더 촘촘히 보려면 215문항 자가진단도 고를 수 있어요.
