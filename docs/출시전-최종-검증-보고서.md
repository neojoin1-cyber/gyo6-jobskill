# 출시 전 PC·모바일·교사 기능 최종 검증 보고서

검증일: 2026-08-27

## 결론

- 학생 PC 자율학습 6과목, 자기소개서, 지원동기, 1분 자기소개, 마지막 한마디는 한 단계씩 진행하는 흐름으로 연결되어 있다.
- 교사는 담당 학급을 바꾸면 학급별 최근 위치, 다음 수업, 학생 참여·오답·도움 신호가 함께 바뀐다.
- 교실 수업은 학생 앱의 같은 학습 장면을 넓게 사용하며, 교사 지원은 수업 맥락을 유지한 채 별도로 연다.
- PC와 휴대폰은 사용자별 키 단위 변경분을 5분 묶음 또는 명시적 저장 시 한 RPC로 교환한다.
- 공개 체험은 제작 중 시간 제한 없이 전체 경로를 점검할 수 있고 서버 쓰기는 차단된다.

## 학생 실제 점검

1. 홈에서 6개 학습관의 목표와 다음 학습을 확인했다.
2. 6과목 모두 첫 단원으로 진입하고 `학습 시작` 뒤 상황·질문·선택지가 실제로 바뀌는 것을 확인했다.
3. 면접은 6개 기초 과정 뒤에 지원처별 심화, 기업·기관 연구소, 답변 연결실이 순서대로 배치된다.
4. 자기소개서는 지원서 선택 뒤 `지원처 → 직무 → 전공 → 경험·근거 → 동기·기여 → 문항 → 완성·첨삭`으로 잠금 해제된다.
5. 면접 답변은 `1분 자기소개 → 지원동기 → 마지막 한마디 → 연결 점검·교사 첨삭`으로 진행된다.
6. 각 자율학습 단원은 능동 응답과 3문항 형성평가를 포함하며, 한 문항은 이해를 전이해야 푸는 변형 문제다.
7. 탐험 탭을 다시 누르면 깊이 들어간 화면에서 과목 목록으로 돌아간다.

## 교사 실제 점검

1. 3개 학급을 전환해 학급별 다음 수업과 학생 현황이 서로 다르게 표시되는 것을 확인했다.
2. `다음 수업`은 해당 학생 학습 장면으로 바로 연결되고 뒤로가기는 직전 학급 화면으로 복귀한다.
3. 학급 캠퍼스 한 화면에서 참여, 푼 문항, 미해결 오답, 도움 필요, 학생별 메시지를 확인한다.
4. 진단, 약한 영역, 학습 진도, 성취, 인성검사, 자기소개서 첨삭, 면접 코칭으로 이동한다.
5. 자기소개서 첨삭에서 문항별 원문, 글자 수, 평가 기준, 문제 표시, 빠른 의견, 수정 요청·승인을 확인했다.
6. 상단과 본문에 중복되던 수업 시작·메시지·첨삭 버튼 묶음을 제거하고, 학급별 `다음 수업`을 주 행동으로 남겼다.

## 공용 PC·동기화·부하

- 브라우저 인증은 탭별 `sessionStorage`, 개인 학습자료는 `sst.user.{사용자UUID}`로 분리한다.
- 공용 PC 로그아웃은 동기화 성공 뒤 현재 계정 사본만 삭제한다.
- 오프라인이면 로그아웃을 멈추며, 사용자가 원할 때만 기기 기록을 폐기하고 로그아웃한다.
- 동기화 도중 추가 입력은 이미 전송된 것으로 처리하지 않고 다음 묶음에 남긴다.
- 항목 400KB, 클라이언트 묶음 1.2MB, 서버 묶음 1.5MB 상한을 둔다.
- 학생 수업 확인 폴백은 1분 고정 조회에서 4~6분 분산 조회로 낮췄다.
- 요점정리는 학생에게만 증분 전달하고, 과목 진행률은 바뀐 값만 전송한다.
- 로컬 웹 저장은 계정별 격리이지 암호화가 아니다. 같은 브라우저의 개발자 도구까지 막는다고 주장하지 않는다.
- 서버 저장은 로그인 사용자 RLS와 공개 체험 쓰기 차단을 적용한다.

## 출시 자동화

1. 로컬 출시 전에는 `npm run release:verify` 한 명령으로 운영 마이그레이션, 실제 학생 교차 동기화, 전체 품질 게이트, Android 종료·복구를 실행한다.
2. GitHub Pages 수동 출시에서는 `remote-preflight`와 `android-preflight`가 모두 통과해야 빌드와 배포가 시작된다.
3. 신규 마이그레이션, 운영 계정 생성·정리, 동기화 충돌·RLS, Android 학습 화면 복구 중 하나라도 실패하면 출시를 차단한다.
4. 세부 운영 방법과 필요한 GitHub Actions secrets 이름은 `docs/RELEASE_AUTOMATION.md`에 기록했다.
