# 요점정리 규격 — NCS 26v1 하위능력 21개

## 왜 만드나

NCS 자율학습에서 학생이 `문서소통능력`을 골라도 **의사소통능력 영역 전체**
요점이 뜬다. 요점정리가 영역(7개) 단위로만 있기 때문이다. 직업공통은 단원(51개)
단위라 고른 것과 배우는 것이 일치하는데, NCS 만 겨냥이 굵다.

하위능력(21개) 단위로 만들면 **고른 것과 배우는 것이 같아진다.**

## 대상

특성화고·마이스터고 학생. 곧 공기업·대기업 필기와 현장실습을 앞두고 있다.
문제를 풀기 **전에** 읽는 글이다. 요약본이 아니라 **판단 기준**을 준다.

## 스키마 (기존 요점정리와 동일해야 한다)

```json
{
  "title": "문서소통능력 요점",
  "intro": "2~3문장. 이 능력이 실제 업무의 어떤 장면에서 쓰이는지.",
  "keyPoints": [
    {
      "topic": "문서에서 요청·기한·조건 골라내기",
      "learn": "💡 로 시작하는 판단 기준 2~4문장.\n💼 예) 로 시작하는 업무 장면 예시 1~2문장.",
      "sampleQuestion": "발문\n\n지문(있으면)\n\n① 보기\n② 보기\n③ 보기\n④ 보기\n\n→ 정답: ③",
      "mode": "이해"
    }
  ],
  "mustRemember": ["시험 직전에 훑을 한 줄 5개"],
  "terms": [{ "word": "용어", "def": "한 문장 정의" }],
  "tips": ["문제 풀 때의 요령 3개"]
}
```

- `keyPoints` 는 **6~8개**. 그 하위능력의 요소(3개)를 고루 덮는다.
- `learn` 은 반드시 `💡` 로 시작하고, 예시 줄은 `💼 예)` 로 시작한다.
- `sampleQuestion` 은 보기를 `①②③④` 로 쓰고 마지막 줄을 `→ 정답: ③` 형태로 끝낸다.
  **정답은 하나만 참이어야 한다.** 지문 없이 상식으로 풀리면 안 된다.
- `mode` 는 `이해` / `적용` / `종합` 중 하나. 6~8개가 한쪽에 몰리지 않게 한다.
- `mustRemember` 5개, `terms` 3~5개, `tips` 3개.

## 근거

`D:\apps\sugar-salt-build\_data\ability-list.json` 에 하위능력마다 고용노동부
표준 원문에서 뽑은 **상황(C)·지식(K)·기술(S)·평가준거**가 들어 있다.
`keyPoints` 는 그 안의 내용에서 나와야 한다. 표준에 없는 것을 지어내지 않는다.

## 문체

- 존댓말 설명체. 학생에게 말하듯 짧게.
- 훈계·미사여구 금지. "~해야 합니다" 반복 대신 **기준과 장면**으로 말한다.
- 특정 기업·기관·연도 기출을 실제인 것처럼 쓰지 않는다.
- 마크다운 표시(`**`, `#`)를 문장 안에 넣지 않는다. 이모지는 규격에 정한 것만.
