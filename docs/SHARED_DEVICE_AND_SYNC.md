# 공용 PC·오프라인·기기 동기화 운영 기준

## 목표

- 한 PC를 여러 학생과 교사가 사용해도 계정 간 초안·학습 기록이 섞이지 않는다.
- 교실 인터넷이 잠시 끊겨도 캐시된 콘텐츠 학습과 작성은 계속된다.
- 서버 요청은 로그인, 5분 묶음 동기화, 사용자의 즉시 동기화, 안전 로그아웃에 집중한다.
- 학생이 과목별 기록을 직접 초기화하고 다시 학습할 수 있다.

## 적용한 흐름

### 로그인

1. Supabase 세션의 사용자 UUID를 확인한다.
2. `sst.user.{uuid}.` 저장 공간만 활성화한다.
3. 프로필을 불러오고 사용자 확인 시각을 갱신한다.
4. 기기 상태를 한 번 묶음 동기화한 뒤 학습 화면을 연다.
5. 오프라인이면 사용자별 캐시 프로필과 로컬 기록으로 계속한다.

### 학습 중

- 정적 콘텐츠와 문항은 앱/PWA 캐시에서 읽는다.
- 진행·오답·초안은 사용자별 로컬 저장 공간에 즉시 기록한다.
- 학습 근거 outbox와 기기 상태는 5분 단위로 묶어 보낸다.
- 네트워크가 복구되면 한 번 동기화한다.
- 사용자 요청 시 `지금 동기화`로 즉시 PC·휴대폰 이어하기 상태를 만든다.

### 사용자 확인

- 온라인 상태에서 24시간마다 서버 사용자 확인을 시도한다.
- 인터넷 단절만으로 로그아웃하거나 작성 내용을 버리지 않는다.
- 마지막 확인 후 72시간까지 오프라인 학습을 허용한다.
- 72시간이 지나면 자료를 지우지 않고 재연결 화면으로 잠근다.

### 로그아웃

- 학생·교사·학교관리자·운영자 로그아웃은 `저장 후 로그아웃` 확인창을 먼저 연다.
- 확인창은 기기 자동 저장 여부, 서버 동기화 대기 건수, 공용 PC 사본 제거 조건을 표시한다.
- 먼저 최대 8초 동안 마지막 묶음 동기화를 시도한다.
- 공용 PC 모드에서는 동기화 성공 후 해당 계정의 기기 사본만 지운다.
- 공용 PC에서 오프라인 또는 동기화 실패 시에는 로그아웃을 멈추고 재연결을 안내한다.
- 바로 자리를 비워야 하면 사용자가 `기기 기록 삭제 후 로그아웃`을 명시적으로 선택할 수 있다.
- 개인 기기에서는 실패한 자료를 계정별 공간에 보존하고 다음 연결 때 다시 보낸다.
- 다른 사용자는 로그인해도 이전 계정의 공간을 앱에서 읽을 수 없다.

### 브라우저·앱 종료

- 입력·선택·학습 위치는 발생 즉시 계정별 기기 공간에 저장한다.
- 화면이 숨겨질 때 변경 대기분의 서버 동기화를 시도한다.
- 변경 대기분이 있을 때만 브라우저 이탈 경고를 연결한다.
- 브라우저 정책상 탭 닫기 대화상자의 문구와 버튼 이름은 웹앱이 바꿀 수 없다. 앱 안의 로그아웃에서는 맞춤 `저장 후 로그아웃` 버튼을 제공한다.
- Android 종료는 `저장 후 종료`를 거치며, 오프라인이면 같은 계정의 기기 공간에 보관한다.
- 갑작스러운 전원 종료나 브라우저 강제 종료 뒤에는 같은 계정으로 다시 로그인해 로컬 사본을 복구·동기화한다.

## 충돌·삭제 규칙

- 서버는 전체 파일이 아니라 논리 키별 최신 수정 시각을 비교한다.
- 서로 다른 과목을 두 기기에서 수정해도 한 기기가 전체 진행을 덮어쓰지 않는다.
- 삭제는 tombstone으로 동기화하여 다른 기기에서 옛 자료가 되살아나지 않게 한다.
- 전송 중 같은 문장을 다시 수정하면 키별 `syncedAt` 비교로 새 수정본을 계속 대기 상태에 둔다.
- 서버 응답을 적용하기 직전에 로컬 수정 시각을 다시 읽어 작성 중인 문장을 원격 값으로 덮지 않는다.
- 학생은 `나 > 계정·기기`에서 과목별 학습 기록을 선택해 초기화한다.

## 보안 경계

- 데이터베이스의 `user_device_state`는 RLS로 `user_id = auth.uid()`만 허용한다.
- 공개 체험 계정은 서버 쓰기가 차단된다.
- 사용자 UUID 기반 로컬 분리는 일반 화면에서 계정 간 노출을 막지만, OS 관리자나 개발자 도구를 막는 암호화는 아니다.
- 암호화 키를 같은 localStorage에 넣는 방식은 보안 효과가 없으므로 사용하지 않는다.
- 현재 공용 PC 보호의 기본은 **동기화 성공 후 로컬 사본 제거**다.
- 장기 보관이 꼭 필요한 공용 PC에는 다음 단계로 IndexedDB AES-GCM과 WebAuthn/기기 키 저장소로 감싼 비추출 키를 적용한다. 키 복구, 비밀번호 분실, 학교 PC 초기화 정책까지 정한 뒤 도입해야 한다.

## 부하 기준

- 화면 전환·문항 응답마다 사용자 확인 API를 호출하지 않는다.
- 인증은 Supabase 세션 자동 갱신을 사용하고, 권위 있는 사용자 확인은 24시간 주기다.
- 상태 동기화는 여러 변경을 한 RPC로 보내며 최대 250개 항목으로 제한한다.
- 클라이언트는 항목당 400KB, 묶음당 1.2MB에서 먼저 멈추고 서버는 1.5MB 상한을 다시 검사한다.
- 요점정리는 학생만 변경분을 받으며, 교사·관리자는 해당 콘텐츠를 자동으로 다시 받지 않는다.
- 수업 참여 여부는 실시간 변경과 화면 복귀를 우선하고, 복구용 조회는 학생별 4~6분으로 분산한다.
- 과목 진행률은 0%와 이전 전송값이 같은 경우 다시 보내지 않는다.
- 로컬 outbox는 XP가 아니라 정답 수·활동 근거만 보내 서버가 점수를 계산한다.

## 다음 출시 점검

- 실제 학생 계정 두 개로 같은 Windows 계정의 브라우저를 번갈아 로그인해 교차 노출이 없는지 확인한다.
- 같은 학생 계정으로 PC와 휴대폰에서 서로 다른 과목을 수정한 뒤 병합되는지 확인한다.
- 오프라인 작성, 브라우저 이탈 경고, Android 저장 후 종료, 재접속을 점검한다.
- 동기화 실패 시 공용 PC 로그아웃 차단과 명시적 기기 폐기를 각각 점검한다.
- 학교가 요구하는 개인정보 보유기간과 삭제 요청 절차를 관리자 화면에 연결한다.
- 교사 학급 화면에 학생별 `마지막 동기화`와 `오프라인 보관 중` 신호를 추가해 제출 누락과 연결 장애를 구분한다.
