## 2. 이번에 새로 들어가는 것

체험자가 보게 될 변화다. 안내 문구를 쓸 때 참고할 것.

- **교사 가로 수업 모드** — 세로/가로 선택, 프로젝터용 화면 재구성
- **수업 자료(덱)를 앱 안에서** — 외부 사이트로 나가지 않음
- **학생 앱의 모든 문항 유형이 교실 화면에** — 듣기(다시 듣기 가능)·매칭·빈칸·서술형
- **수업 참여 확인** — 학생이 앱을 보고 있는지
- **「학생 앱에서 여기」 안내 + 따라가기**
- **문항 정비** — NCS 실제 시험과 같은 4지선다로 762문항, 화면에 안 나오던 94문항 복구

## 3. 작업 순서

### 3-1. 개발 담당에게서 받을 것

```
dist/  (빌드 산출물 한 벌)
```

- 약 23MB · 57개 파일
- **반드시 「홈페이지용」으로 빌드된 것을 받을 것.** 경로 설정이 다르면 화면이 안 뜬다(§4-1).

### 3-2. 갈아 끼우기

1. 홈페이지 저장소에서 `apps/sugar-salt/` 아래 **`assets/` 폴더를 통째로 비운다.**
   - 옛 번들이 남아 있어도 새 `index.html` 이 참조하지 않아 **용량만 늘어난다.**
2. 받은 `dist/` 의 내용을 `apps/sugar-salt/` 로 복사한다.
3. **아래 두 가지는 덮어쓰지 말고 유지·확인할 것** (§4)
   - `index.html` 의 파비콘 경로와 `trial-responsive.css` 줄
   - `.nojekyll` (저장소 최상위, 이미 있음)
4. 커밋 → `main` 푸시 → GitHub Actions 배포 완료 대기(수 분)

### 3-3. 배포 확인

```
https://gyo6.kr/apps/sugar-salt/
```

- 브라우저 **강력 새로고침**(Ctrl+Shift+R) 후 확인. 서비스 워커 때문에 옛 화면이
  남을 수 있다(§4-3).
- 페이지 소스에서 `assets/index-BiIuZ-dd.js` 가 보이면 갱신 성공.

## 4. 반드시 지킬 것 — 안 지키면 화면이 안 뜬다

### 4-1. 경로(base) 설정

이 앱은 **`/apps/sugar-salt/` 하위**에서 도는 것을 전제로 빌드해야 한다.
개발 담당에게 받을 때 **「gyo6.kr/apps/sugar-salt/ 용」이라고 명시해 요청할 것.**

> 잘못된 빌드를 올리면 흰 화면만 뜨고 콘솔에 파일 404 가 쏟아진다.
> 현재 올라간 것은 상대경로(`./assets/...`)로 되어 있어 정상이다. 이 방식을 유지한다.

### 4-2. `index.html` 의 홈페이지 전용 두 줄

현재 올라간 `index.html` 에는 홈페이지에서 추가한 줄이 있다. 새 파일로 덮어쓸 때
**빠지지 않게 다시 넣을 것.**

```html
<link rel="icon" href="../../brand/logo/favicon.svg" type="image/svg+xml" />
<link rel="stylesheet" href="./assets/trial-responsive.css?v=20260728-desktop-shell" />
```

- 첫 줄 — 홈페이지 파비콘. 없으면 탭 아이콘이 깨진다.
- 둘째 줄 — 홈페이지에서 만든 반응형 보정. **`trial-responsive.css` 파일도 함께 유지할 것.**
  (개발 담당의 `dist/` 에는 이 파일이 없다. 지우지 말 것.)

### 4-3. 서비스 워커 — 옛 화면이 남는 문제

이 앱은 오프라인 동작을 위해 서비스 워커(`sw.js`)를 쓴다. 그래서 **파일을 갈아
끼워도 체험자 브라우저에 옛 화면이 계속 뜰 수 있다.**

- `sw.js` 와 `registerSW.js` 를 **반드시 새 것으로 함께 교체**할 것.
- 배포 후 본인 브라우저에서 강력 새로고침으로 확인.
- 체험자에게는 안내 페이지에 한 줄 넣는다 —
  「화면이 예전 것으로 보이면 새로고침(Ctrl+Shift+R)을 해 주세요.」

### 4-4. 캐시 설정

Cloudflare 를 쓰고 있다. 배포 후에도 옛 파일이 계속 나가면
**Cloudflare 캐시 퍼지**를 한 번 실행할 것.

## 5. 하지 말 것

1. **`apps/sugar-salt/` 밖의 파일을 건드리지 말 것.** 홈페이지 다른 페이지와 무관하다.
2. **`dist/` 안의 파일 이름을 바꾸지 말 것.** 파일명에 붙은 해시가 캐시를 구분한다.
3. **`index.html` 을 손으로 편집해 번들 경로를 바꾸지 말 것.** §4-2 의 두 줄만 추가한다.
4. **옛 `assets/` 를 남겨 두지 말 것.** 동작에는 지장 없지만 저장소가 계속 커진다.
5. 체험본과 안내 페이지를 **동시에 공개하지 말 것.** 배포 확인(§3-3)이 끝난 뒤
   안내 페이지의 링크를 살린다.
