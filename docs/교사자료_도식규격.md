# 수업 덱 보조자료 규격 — 도식·실전 예시

교사 덱은 지금 `표지 → 오늘의 전략 → 문항 8개 → 출구 질문`뿐이다. 개념을 눈으로
보여 줄 도식도, 실제 채용시험이 어떻게 묻는지 보여 줄 예시도 없다. 두 가지를
차시마다 붙인다.

## 왜 SVG를 직접 쓰지 않게 하나

도식을 손으로 그린 SVG로 받으면 좌표가 어긋나고 글자가 상자 밖으로 나간다.
그래서 **무엇을 그릴지만 구조로 적고**, 그리는 일은 파이썬이 한다. 같은 규칙으로
그리므로 63차시가 한 벌처럼 보이고, 나중에 색·글꼴을 한 번에 바꿀 수 있다.

## 1. 도식 (`diagram`)

세 가지 꼴만 쓴다. 억지로 다른 꼴을 만들지 말고 셋 중 맞는 것을 고른다.

### `flow` — 순서가 있는 절차
```json
{
  "kind": "flow",
  "title": "문서를 읽는 네 단계",
  "steps": [
    { "label": "목적 확인", "detail": "누가 왜 보냈나" },
    { "label": "구조 훑기", "detail": "제목·소제목·표" },
    { "label": "핵심 표시", "detail": "기한·조건·요청" },
    { "label": "행동 정리", "detail": "내가 할 일 한 줄" }
  ]
}
```
- `steps`는 3~5개. 각 `label` 12자 이내, `detail` 20자 이내.

### `matrix` — 두 축으로 나누는 판단
```json
{
  "kind": "matrix",
  "title": "업무 우선순위",
  "xAxis": { "low": "덜 급함", "high": "급함" },
  "yAxis": { "low": "덜 중요", "high": "중요" },
  "cells": [
    { "x": "high", "y": "high", "label": "즉시 처리", "detail": "오늘 안에" },
    { "x": "low",  "y": "high", "label": "일정 잡기", "detail": "날짜 확정" },
    { "x": "high", "y": "low",  "label": "위임·간소화", "detail": "빠르게 처리" },
    { "x": "low",  "y": "low",  "label": "나중에",     "detail": "목록에만" }
  ]
}
```
- `cells`는 정확히 4개, 네 조합이 모두 있어야 한다.

### `compare` — 헷갈리는 두 가지를 가르기
```json
{
  "kind": "compare",
  "title": "보고와 공유",
  "left":  { "name": "보고", "points": ["판단을 요청", "상급자 대상", "결론 먼저"] },
  "right": { "name": "공유", "points": ["정보를 전달", "동료 대상", "맥락 먼저"] }
}
```
- `points`는 좌우 각각 3개, 각 18자 이내. 좌우가 **같은 관점끼리 짝**이 되게 쓴다.

## 2. 실전 예시 (`realWorld`)

```json
{
  "examTypes": [
    {
      "org": "공공기관 NCS 필기",
      "pattern": "회의록·공문을 주고 '지시받은 사람이 할 일'을 고르게 한다",
      "trap": "지시 대상이 아닌 사람의 할 일을 보기에 섞어 둔다",
      "howTo": "누가 누구에게 지시했는지부터 표시하고 읽는다"
    },
    { "org": "대기업 인적성", "pattern": "...", "trap": "...", "howTo": "..." }
  ],
  "workCase": {
    "title": "20자 이내 제목",
    "situation": "실제 업무 장면 3~4문장. 특정 회사 이름을 쓰지 않는다.",
    "whatWentWrong": "이 능력이 없을 때 무엇이 어긋나는지 2문장",
    "betterWay": "이 능력을 쓰면 어떻게 달라지는지 2문장"
  }
}
```
- `examTypes`는 2개. `org`는 `공공기관 NCS 필기` / `대기업 인적성` /
  `금융권 필기` / `공기업 전공·직무` 중에서 고른다.
- **지어낸 기출 문항을 그대로 싣지 않는다.** 실제 문제를 인용하는 것이 아니라
  *어떤 식으로 묻는지*를 설명한다. 특정 연도·기관의 실제 문항이라고 쓰면 안 된다.
- `workCase.situation`에 실존 기업명·인명을 쓰지 않는다.

## 공통

- 한 차시(`element`)당 `diagram` 1개 + `realWorld` 1개.
- 존댓말 설명체. 학생에게 직접 말하지 말고 **교사가 읽어 줄 자료**로 쓴다.
- 문장에 `**`, `#` 같은 마크다운 표시를 넣지 않는다. 평문만.
