## 4. 조사할 가설 — 이 순서로

### 가설 A. 앱 번들과 원격 상태의 불일치 (우선순위 1)

앱은 번들 자산으로 뜨지만 **원격 값에 따라 화면을 바꾸는 지점**이 있다.

- `src/App.jsx:129-160` — Supabase `app_config`(`min_build`, `latest_build`, `latest_version`, `store_url`)로
  업데이트 상태(`soft`/`hard`)를 판정한다.
- 확인할 것: 운영 `app_config` 의 현재 행 값, 그리고 `latest_build`/`min_build` 가
  설치본 build(`29803019`)와 어떤 관계일 때 어떤 화면이 뜨는지.
  값이 비었거나(`null`) 형이 다르면 비교식이 무엇을 던지는지 확인.
- [검증필요] `app_config` 를 읽지 못했을 때(네트워크·RLS) 예외가 렌더 경로로 전파되는가.

### 가설 B. 4.8.13에서 새로 추가된 학습 연결(presence) 경로 (우선순위 2)

4.8.13 커밋 `4824727` 이 추가한 것 중 렌더 경로에 붙은 것:

- `src/lib/learningPresence.js` (신규 87줄)
- `src/screens/student/StudentShell.jsx` (+31줄)
- `src/screens/teacher/TeacherLearningPreview.jsx` (+151줄)
- `src/screens/teacher/TeacherWorkspace.jsx` (91줄 변경)

확인할 것: 이 경로들이 `rpc_learning_presence_ping` / `rpc_class_live` 응답 형태를 그대로 신뢰하는지,
응답이 `{error: …}` 이거나 필드가 없을 때 옵셔널 체이닝 없이 접근하는 곳이 있는지.

### 가설 C. WebView 런타임 차이 (우선순위 3)

데스크톱 Chromium에서는 통과하고 기기 WebView에서만 깨지는 문법·API.

- 확인할 것: 번들 산출물에 남아 있는 최신 문법(`Object.groupBy`, `Array.prototype.at`, `structuredClone`,
  정규식 `v` 플래그, CSS `:has()` 의존 로직 등)과 대상 기기 WebView 버전.
- `android/app/build.gradle` 의 `minSdkVersion`, 그리고 사용자 기기의 Android System WebView 버전 확인.

### 가설 D. 저장소 잔존값으로 인한 크래시 (우선순위 4)

- 기기에 남아 있던 이전 버전의 키가 새 코드에서 다른 형태로 읽히는 경우.
- 관련 키(클로드 코드 실측): `sst.legacy-owner`, `sst.user.<uuid>.__device_meta__`,
  `sst.user.<uuid>.sst.student.learning.routes.v1`.
- 검증법: 앱 데이터 삭제 후 재실행으로 증상이 사라지는지. **사라지면 마이그레이션 결함이다.**
