# 학생 취업 프로필 기반 자기소개서·면접 개인맞춤 개편 계획

## 1. 제품 방향

자기소개서관과 면접 스킬관에 각각 정보를 다시 입력하게 하지 않는다. 학생이 한 번 정리한 전공, 자격, 활동, 경험 근거를 두 학습관과 교사 첨삭이 함께 사용하는 `학생 취업 프로필`로 통합한다.

이 기능의 목표는 문장을 대신 만들어 주는 것이 아니다.

1. 학생이 실제로 한 일을 빠뜨리지 않고 찾는다.
2. 지원 직무와 질문에 맞는 근거를 골라 준다.
3. 근거가 부족한 영역은 앞으로 할 수 있는 작은 보완 활동으로 바꾼다.
4. 자기소개서와 면접 답변이 서로 다른 사람의 이야기처럼 어긋나지 않게 한다.
5. 교사가 학생의 원본 경험과 수정 과정을 보고 지도하게 한다.

기존 `cover_letter_evidence`와 지원처별 자기소개서·면접 답변 연결, 교사 첨삭 기능은 유지한다. 근거은행을 폐기하거나 새 기능과 중복시키지 않고 취업 프로필의 핵심 자료로 승격한다.

## 2. 경쟁력의 핵심

### 하나의 근거, 여러 결과물

- 전공 실습 한 건을 직무역량 자기소개서, 경험 면접, 1분 자기소개에 각각 맞는 길이와 구조로 활용한다.
- 같은 근거를 사용하더라도 질문 의도에 따라 강조할 행동과 결과를 다르게 안내한다.
- 자기소개서에서 사용한 근거와 면접 답변의 내용이 충돌하면 제출 전에 알린다.

### 설명 가능한 개인맞춤

- 추천 카드마다 `왜 이 근거를 추천했는지`를 표시한다.
- 예: `전기설비 직무`, `안전 기준`, `직접 측정`, `오결선 수정`이 현재 질문과 맞아서 추천.
- 자동 생성 결과만 보여 주지 않고 학생이 근거를 선택하고 수정하는 과정을 남긴다.

### 부족함을 준비 행동으로 전환

- 수상이나 봉사 시간이 적다고 낮은 점수를 주지 않는다.
- 경험 범위를 `전공 적용`, `문제 해결`, `협업`, `소통`, `책임·안전`, `개선·성과`로 보여 준다.
- 비어 있는 범위에는 실제로 수행 가능한 보완 미션을 제시한다.
- 예: 실습 점검표 만들기, 작업 전후 시간 비교하기, 학급 역할 기록하기, 교사 피드백 받기.

### 교사 검증과 성장 이력

- 학생이 공유한 근거만 교사가 확인한다.
- 교사는 `사실 확인`, `학생 역할 더 구체화`, `결과 근거 보완`으로 피드백한다.
- 수정 전후와 확인 상태를 남겨 대신 써 주는 첨삭이 아니라 학생의 성장 기록이 되게 한다.

### 낮은 서버 비용

- 학과·자격·직무·질문·역량의 태그 매칭은 기기에서 실행한다.
- 입력 즉시 사용자별 기기 공간에 저장하고 변경분만 서버와 동기화한다.
- AI 호출이 없어도 핵심 추천과 작성 흐름이 동작한다.
- AI 문장 점검은 출시 후 선택 기능으로 분리하고 사용자가 요청한 순간에만 실행한다.

## 3. 수집 정보 원칙

### 추천에 사용하는 정보

- 학교 등록 때 확인한 학과와 학년
- 관심 산업과 지원 직무
- 전공 수업·실습에서 사용한 도구, 기술, 기준
- 자격증의 취득·준비·관심 상태
- 현장실습, 프로젝트, 동아리, 학급 역할, 아르바이트, 봉사, 수상, 개인 학습
- 각 활동에서 학생이 직접 맡은 역할, 행동, 결과, 확인 자료
- 학생이 선택한 강점과 보완 목표

### 수집하거나 추천에 사용하지 않는 정보

- 성별에 따른 자기소개서·면접 추천
- 외모, 신체 조건, 출신지역, 가족관계, 혼인 여부, 재산
- 직무와 무관한 건강·종교·정치 정보
- 주민등록번호와 불필요한 생년월일

성별은 블라인드 채용의 편견 요소이며 직무역량 추천에 필요하지 않다. 음성 높이, 말투, 복장도 성별 고정관념으로 추천하지 않고 발음 명료도, 속도, 시선, 질문 적합성처럼 모든 학생에게 같은 기준을 적용한다.

개인정보 보호법상 목적에 필요한 최소정보만 수집하고, 선택정보를 입력하지 않아도 기본 학습은 이용할 수 있어야 한다. 학생은 언제든 수정·삭제·내보내기·교사 공유 해제를 할 수 있어야 한다.

## 4. 데이터 구조

### `student_career_profiles`

- `student_id`: 학생 계정
- `major_group`: 기존 10개 전공 대분류
- `department_label`: 학교에서 사용하는 실제 학과명
- `target_sectors`: 금융권·공공기관·대기업 등 관심 분야
- `target_job_families`: 관심 직무와 NCS 세분류
- `strength_tags`: 학생이 확인한 강점
- `growth_tags`: 보완하고 싶은 역량
- `onboarding_completed_at`: 첫 준비 완료 시각
- `teacher_share_scope`: 비공개·선택 공유·첨삭 제출 시 공유
- `updated_at`

### `student_qualifications`

- 자격 종목, 발급기관, 상태(`관심`, `준비 중`, `취득`), 취득일
- 자격과 연결되는 NCS·직무·기술 태그
- 증빙 이름 또는 확인 메모. 증명서 원본 파일 업로드는 1차 출시에서 제외한다.

### 기존 `cover_letter_evidence` 확장

- 현재 전공 분야, 경험 출처, 상황, 역할, 행동, 결과, 확인 근거, 기술 태그는 유지한다.
- `activity_type`, `start_date`, `end_date`, `status`, `verification_status`, `verified_by`, `verified_at`, `visibility`, `updated_at`을 추가한다.
- 삭제만 가능한 현재 화면에 수정, 복제 후 보완, 보관 기능을 추가한다.
- 이름은 화면에서 `자기소개서 근거은행`이 아니라 `내 경험·근거`로 통일한다.

### `career_content_map`

학과별·자격별 문장을 모두 별도로 만들면 조합 수가 폭증하고 내용이 반복된다. 다음 태그를 가진 하나의 콘텐츠 지도로 관리한다.

- 학과·전공 영역
- NCS 직무·능력단위
- 자격 종목
- 경험 유형
- 역량·행동 태그
- 자기소개서 질문 유형
- 면접 질문 유형
- 산업·지원처 유형
- 난이도, 최신 확인일, 출처

하나의 사례가 여러 태그와 연결되도록 하여 자료가 늘수록 추천 품질이 함께 높아지게 한다.

## 5. 학생 화면과 직선형 흐름

### 공통 진입점

하단 `나` 화면을 다음 세 구역으로 정리한다.

1. `취업 프로필`
2. `계정·기기`
3. `내 순위`

자기소개서관과 면접 스킬관에는 별도 입력 메뉴를 만들지 않는다. 두 학습관의 시작 화면에서 같은 `내 경험 준비` 상태를 보여 주고 공통 취업 프로필로 연결한다.

### 최초 5분 준비

회원가입 단계에서는 학교·학과·학급 등 서비스에 필요한 정보만 받는다. 긴 경력 입력을 강제하면 가입 이탈과 개인정보 부담이 커지므로, 자기소개서관 또는 면접 스킬관을 처음 시작할 때 다음 순서로 진행한다.

1. 목표 선택: 관심 산업과 직무 1~3개
2. 준비 현황: 자격 취득·준비·관심 상태
3. 활동 고르기: 전공 실습, 프로젝트, 동아리, 학급 역할, 아르바이트, 봉사 등
4. 첫 근거 만들기: 선택한 활동 하나를 역할·행동·결과로 정리
5. 준비 지도 확인: 지금 쓸 수 있는 근거와 다음 보완 행동

각 단계에는 `나중에 입력`을 제공하되, 건너뛰면 개인맞춤 범위가 줄어든다는 사실만 간단히 알린다.

### 이후 사용

- 첫 화면에는 `이어서 준비할 것 1개`만 주요 버튼으로 보여 준다.
- 새 활동이 생기면 `내 경험·근거 추가`에서 기록한다.
- 자격증 상태는 관심 → 준비 중 → 취득으로 바꿀 수 있다.
- 프로필 수정은 작성 중인 자기소개서나 면접 답변을 지우지 않는다.
- 수정된 정보가 기존 답변에 영향을 주면 `새 근거로 다시 점검`을 제안한다.

## 6. 자기소개서 개인맞춤

기존 `지원처 → 직무 → 전공 → 경험·근거 → 동기·기여 → 문항 → 완성·첨삭` 순서를 유지한다.

### 경험·근거 단계

- 현재 질문과 지원 직무에 맞는 근거 3개를 추천한다.
- 추천 이유와 부족한 항목을 함께 표시한다.
- 근거를 선택하면 원문을 그대로 붙여 넣지 않고 질문에 필요한 `상황`, `행동`, `결과` 메모만 가져온다.
- 학생이 먼저 문장을 작성한 뒤 구조 점검과 비교 예시를 연다.

### 자동 점검

- 지원처·직무·질문 요구와 근거의 연결
- 학생이 직접 한 행동인지 여부
- 수치·완성물·피드백 등 결과 확인 가능성
- 다른 지원서의 회사명·사업명 혼입
- 블라인드 채용에서 제외할 인적사항
- 면접 답변과 사실·수치 불일치

## 7. 면접 개인맞춤

### 맞춤 준비 묶음

학생의 목표 직무와 근거를 바탕으로 다음 순서로 한 묶음을 만든다.

1. 예상 질문 5개
2. 질문별 추천 근거 1~3개
3. 답변 구조 선택
4. 학생 답변 작성·녹음
5. 질문 적합성, 직접 행동, 결과, 말하기 시간 점검
6. 1분 자기소개 → 지원동기 → 마지막 한마디 연결 점검
7. 교사 첨삭 제출

### 질문 구성

- 공통 질문: 자기소개, 지원동기, 강점·약점, 협업, 갈등, 실패, 윤리
- 직무 질문: 학생의 학과·자격·NCS 직무 태그와 연결
- 근거 꼬리 질문: 학생이 입력한 역할과 결과를 실제로 확인
- 부족 영역 질문: 준비가 약한 역량을 연습하되 없는 경험을 꾸며내게 하지 않음
- 지원처 질문: 최신 공식 자료를 확인한 경우에만 기관·기업 특화 사실을 사용

## 8. 교사 지도

### 학급 준비 현황

- 취업 프로필 준비 학생 수
- 근거가 0개인 학생, 수정 대기 근거, 교사 확인 요청
- 역량 범위별 경험 보유 현황
- 자기소개서·면접 첨삭 대기와 재제출 현황

학생끼리 활동 개수나 자격증 개수를 순위화하지 않는다. 교사 화면의 목적은 우열 판단이 아니라 지도할 다음 학생을 찾는 것이다.

### 학생 상세

- 학생이 공유한 목표 직무, 자격 상태, 활동·근거
- 근거별 사실 확인과 보완 의견
- 같은 근거가 사용된 자기소개서와 면접 답변
- 수정 전후와 교사 피드백 반영 여부
- 보완 미션 배정과 완료 확인

교사는 학생이 공유하지 않은 개인 메모를 볼 수 없고, 첨삭 제출 시 필요한 근거만 확인한다.

## 9. 콘텐츠 확보 체계

### 1단계: 공식 분류 기반 골격

- 기존 10개 전공 대분류를 실제 학교 학과명과 연결한다.
- NCS 대·중·소·세분류, 능력단위, 지식·기술·태도를 직무 태그의 기준으로 사용한다.
- 국가기술자격과 학과별 취득 가능 자격을 공식 공개 데이터로 연결한다.
- 지원처 정보는 채용공고·직무기술서·기업 공식 자료의 출처와 확인일을 저장한다.

### 2단계: 품질 높은 사례 세트

각 전공 대분류마다 먼저 다음 6종을 확보한다.

- 전공 실습 적용
- 오류·문제 해결
- 안전·품질 기준
- 팀 프로젝트 협업
- 고객·이용자 소통
- 개선과 결과 확인

좋은 사례, 약한 사례, 꼬리 질문, 자기소개서 전환 예시, 면접 전환 예시를 한 세트로 만든다. 성별별 문장을 만들지 않고 직무와 실제 행동별 자료를 늘린다.

### 3단계: 운영 중 확장

- 학생의 원문은 공용 학습 데이터로 자동 사용하지 않는다.
- 별도 동의와 비식별 검수를 거친 패턴만 콘텐츠 개선 후보로 집계한다.
- 교사가 자주 보완한 항목, 학생이 자주 막힌 질문, 추천 후 실제 사용률을 바탕으로 우선 제작한다.
- 콘텐츠마다 출처, 검수자, 버전, 최신 확인일, 적용 직무를 관리한다.

## 10. 추천 엔진

초기 버전은 설명 가능한 태그 점수 방식으로 구현한다.

- 현재 질문 요구와 일치: 25
- 지원 직무·NCS 일치: 25
- 학생이 직접 한 행동의 구체성: 20
- 결과·확인 근거: 15
- 교사 확인: 10
- 최근 수정·활용 가능성: 5

추천 결과는 상위 3개만 보여 주고 점수 대신 이유를 설명한다. 특정 자격이나 활동이 없다고 감점하지 않으며, 성별·학교명·가족 배경은 입력값과 점수에서 제외한다.

AI 기능은 추천 근거를 정한 뒤 문장 구조를 점검하는 보조 역할만 맡긴다. AI가 학생에게 없는 자격, 수상, 역할, 수치, 기업 정보를 만들면 저장과 제출을 막는다.

## 11. 구현 순서

### P0. 기반 정리

- 근거은행 명칭을 `내 경험·근거`로 통일
- 기존 근거 수정·보관 기능 추가
- 공용 PC 사용자 격리, 로컬 암호화 저장, 증분 동기화 범위에 취업 프로필 포함
- 마이그레이션·RLS·계정 삭제·데이터 내보내기 검증 추가

### P1. 공통 취업 프로필

- `나 > 취업 프로필` 화면
- 최초 5분 준비 흐름
- 학과, 목표 직무, 자격 상태, 활동·근거 등록
- 자기소개서관과 면접 스킬관 공통 연결
- 준비 지도와 다음 행동 1개 제공

### P2. 개인맞춤 추천

- 질문·직무·NCS·근거 태그 매칭
- 자기소개서 근거 3개 추천과 추천 이유
- 면접 예상 질문과 꼬리 질문 추천
- 자기소개서·면접 답변 간 사실·수치·지원처 불일치 점검

### P3. 교사 지도

- 학급 준비 현황과 지도 우선순위
- 학생 공유 범위 설정
- 근거 확인, 보완 의견, 보완 미션
- 자기소개서·면접 첨삭 화면에서 원본 근거와 수정 이력 연결

### P4. 콘텐츠 운영과 선택형 AI

- 공식 NCS·자격·직무 데이터 갱신 도구
- 콘텐츠 검수·버전·최신 확인일 관리
- 운영 통계 기반 부족 사례 우선 제작
- 사용자 요청형 AI 점검, 비용 상한, 개인정보 제거, 결과 검증

## 12. 출시 차단 검증

- 기존 근거와 작성본이 마이그레이션 뒤 그대로 보인다.
- 한 계정의 취업 프로필이 PC와 휴대폰에서 같은 내용으로 이어진다.
- 공용 PC에서 로그아웃한 뒤 다른 계정에 이전 학생 자료가 보이지 않는다.
- 학생이 입력하지 않은 사실이 추천문·예시에 섞이지 않는다.
- 성별과 블라인드 편견 요소가 추천 입력·콘텐츠 분기·교사 평가에 사용되지 않는다.
- 학생이 공유하지 않은 근거는 교사와 다른 학생이 읽을 수 없다.
- 근거 수정·삭제·내보내기·계정 삭제가 서버와 모든 기기에 반영된다.
- 자기소개서와 면접에서 같은 근거의 역할·수치·결과가 충돌하면 경고한다.
- 추천 이유가 모든 추천 카드에 표시된다.
- 첫 사용 학생이 도움 없이 `목표 선택 → 첫 근거 저장 → 맞춤 학습 시작`을 완료한다.

## 13. 성공 지표

- 첫 취업 프로필 준비 완료율
- 학생 1명당 사용 가능한 근거 카드 수와 수정 완료율
- 추천 근거가 실제 자기소개서·면접 답변에 사용된 비율
- 자기소개서와 면접 답변의 사실 불일치 감소율
- 교사 첨삭 후 학생 재제출률
- 근거가 없던 학생이 보완 미션 뒤 새 근거를 만든 비율
- PC·휴대폰 동기화 실패율과 공용 PC 자료 노출 사고 0건

핵심 성공 기준은 생성 문장 수가 아니다. 학생이 자신의 실제 경험을 더 구체적으로 이해하고, 그 근거를 지원 직무에 맞게 설명하며, 교사가 그 과정을 확인하고 성장시키는지가 기준이다.
